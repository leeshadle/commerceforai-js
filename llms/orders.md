# CommerceForAI: Orders, shipping and customers

> Orders, editing an order, split shipments, delivery tracking, shipping labels, returns, customers and their account page, reports, events and webhooks.

Part of https://commerceforai.com/llms.txt (start there: setup, rules and the core recipe). SDK calls are `commerce.<resource>.<method>(...)` and return `{ data, error }`; money is in cents.

- customers: list({ q?, sort?: "recent"|"spent"|"orders", page? }) → { email, name, orders, total_spent }; get(email) → totals, last address, order_history. Derived from paid orders by email.
- reports: sales({ days? = 30 }) → totals (orders, gross, net, refunds, discounts, average_order, customers, returning_customers), change vs previous period, series, top_products. Simulated orders excluded.
- orders: list({ status?: "pending_payment"|"paid"|"fulfilled"|"cancelled"|"refunded" | [...] }), get(idOrNumber), update(id, { note?, metadata? }), fulfill(id, { carrier?, tracking_number?, tracking_url? }), refund(id, { amount?, restock?, reason? })
  - "paid" = ready to ship. Orders have a human-friendly `number` (1001, 1002, ...)
- events: list({ after?, type?: "order.*" | "order.paid" | ..., limit? })
- webhooks: create({ url, events? }), list(), remove(id), verify({ payload, headers, secret })
- shipping labels: orders.shippingRates(order, { parcel?, return_id? }) → cheapest first; orders.buyLabel(order, rate_id, { max_cost? }) → marks the order fulfilled with tracking; orders.labels(order)
  - set `weight_oz` on variants so parcels are weighed automatically
- returns: returns.create(order, { items, reason? }), list({ status?, order_id? }), get, approve(id, { return_label?: "cheapest" }), reject(id, { note? }), receive(id, { restock? = true, refund? = true, refund_amount? })
- delivery tracking: order.shipments lists every package (the store's own and print-on-demand) with status: shipped | label_created | in_transit | out_for_delivery | available_for_pickup | delivered | returned | exception, plus delivered_at, eta, detail. order.delivered_at is set once every package is delivered. order.tracking_page_url is the customer's tracking page (the shipping emails link to it; safe to show the customer, it has no name, email or street address). Status is checked every few hours from whoever shipped the package: Printful (full status), Printify (delivered only), or a label bought here through EasyPost/Shippo. A tracking number entered by hand stays "shipped". Customers get one "order shipped" email, an email for every additional package, and a "delivered" email per package (store.update({ delivered_emails: false }) turns those off).
- customer accounts, no passwords: link your site's "My orders" to store.get().customer_account_url (commerceforai.com/account/<store_id>). The customer enters their email and gets a private link (also in every order confirmation email) to a page with their orders, tracking, subscriptions and a "Return items" button. Don't build login or an orders page yourself. customers.get(email).account_url is one customer's link (send it only to them). Return requests arrive as return.requested (requested_by: "customer") and the store's team is emailed; approve or reject as usual. store.update({ returns_window_days: 30 }) sets how long after delivery customers can ask (null: only the store opens returns).
- editing an order (paid, not yet shipped): orders.edit(id, { replace?: [{ variant_id, with_variant_id, quantity? }], remove?: [{ variant_id, quantity }], add?: [...], shipping_address?, email?, waive_difference?, notify_customer? = true, reason?, dry_run? }) → { changes (in words), refund, items_after, fulfillment: [{ provider, action: "cancel_and_resend" }], order }. Removing or swapping to something cheaper refunds that share of what was charged (with its share of tax and discount) and puts stock back; a change that costs more is refused with extra_cost unless waive_difference: true (to charge for extras, send a draft order). Affected Printify/Printful orders are cancelled there and sent again; if the provider refuses (in production), the edit fails and nothing changes. order.subtotal/total stay what was charged; order.items is what ships; order.edits is the history. Use dry_run: true first. The customer gets one "order updated" email per edit. Shipped orders can't be edited: open a return. MCP: edit_order (billing tool set). Event: order.edited.
- split shipments: orders.fulfill(id, { carrier, tracking_number, items: [{ variant_id, quantity }] }) ships one box of the order; it stays status paid with fulfillment_status "partial" and unshipped_items listing what's left, and the customer gets a "part of your order" email for that box. fulfill without items ships whatever is left and completes the order. Each order.shipments[] entry lists its items (print-on-demand packages: that provider's lines). MCP: fulfill_order with items.
- more than one package: orders.fulfill(id, { carrier, tracking_number }) on an order that already shipped adds a package and emails the customer about it; pass replace: true to correct the tracking instead (no email).
Events: order.created, order.paid, order.fulfilled, order.updated, order.cancelled, order.refunded, checkout.expired, checkout.abandoned, inventory.updated, product.created, product.updated, label.created, order.shipment_created, order.shipment_updated, order.shipment_delivered, order.delivered, fulfillment.submitted, fulfillment.failed, fulfillment.canceled, fulfillment.on_hold, return.requested, return.approved, return.rejected, return.completed

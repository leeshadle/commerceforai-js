# CommerceForAI: Checkout and selling

> Checkouts, shipping rates at checkout, discount codes, automatic discounts, gift cards, draft orders and invoices, subscriptions, sales tax, tax-exempt customers, local currencies, abandoned-checkout recovery, and the React cart.

Part of https://commerceforai.com/llms.txt (start there: setup, rules and the core recipe). SDK calls are `commerce.<resource>.<method>(...)` and return `{ data, error }`; money is in cents.

- draft orders and invoices (phone orders, wholesale, quotes): draftOrders.create({ items: [{ variant_id, quantity, unit_price? }], customer_email?, customer_name?, note?, discount_code?, shipping?: { name, amount }, expires_in_days? = 30 }) → { id, number (shown D1001), status, subtotal, invoice_url }. draftOrders.sendInvoice(id, { to?, message? }) emails it with a Pay now link; or send invoice_url yourself. The link opens an invoice page that starts a fresh Stripe checkout when they pay (stock is held only then); paying creates a normal order and the draft becomes completed with order_id. update(id, {...}) until paid; cancel(id); list({ status? }). Custom prices only work on drafts, never on checkouts.create. MCP: save_draft_order, send_invoice, list_draft_orders. Events: draft_order.created, updated, invoice_sent, completed, cancelled.
- local currencies: store.update({ local_currencies: true }) shows shoppers abroad prices in their own currency on Stripe's checkout (Stripe Adaptive Pricing, 150+ countries). The store is still paid in its own currency; the shopper pays Stripe's 2–4% conversion fee. Off by default; if Stripe refuses it for an account, checkout goes ahead in the store's currency.
- subscriptions: give a variant recurring: { interval: "day" | "week" | "month" | "year", interval_count? } (products.create variants, or price + recurring shorthand; variants.update to change). A checkout containing it becomes a Stripe subscription; one-time items in the same cart are charged once. All subscription items in one checkout must share one schedule. Subscription checkouts have no shipping choice: the store's first checkout shipping rate is added as a recurring "Shipping" line. Each paid renewal creates a normal order (metadata.subscription_id; stock, emails, print-on-demand as usual). subscriptions.list({ status?, email? }), get(id) (with its orders), cancel(id, { at_period_end? = true }), simulateRenewal(id) on test stores (simulate_order with a recurring item creates a simulated subscription). Customers manage their own: subscription.manage_url (also linked from every subscription order's confirmation email) opens a page where they cancel at the end of the paid period, or undo that; the store's team gets an email when a customer cancels. The store can also cancel(id) or resume(id). MCP: list_subscriptions, cancel_subscription. Events: subscription.created, renewed, updated, canceled.
- gift cards: giftCards.create({ value (cents), recipient_email?, send?: true, message?, note?, expires_at? }) → { code like K7QX-M2PD-9WRT-H4NB, balance }. Customers type the code in Stripe's code box or you pass it as discount_code; unspent balance stays on the card (a new Stripe code for the rest is made automatically). giftCards.get(id | code | last4) shows uses; update(id, { active?, balance? }); send(id, { to?, message? }). To sell them: products.create({ name: "Gift card", metadata: { gift_card: "true" }, variants: [{ name: "$25", price: 2500 }, ...] }); paying issues one card per unit and emails it to the line's properties.recipient_email (else the buyer), with properties.message; gift-card-only orders need no shipping and are complete once paid. Limits: a card comes off the products, not shipping; it can't combine with another code or an automatic discount; with Stripe Tax on, tax is worked out on the reduced amount (Stripe Checkout has no gift-card payment method). MCP: issue_gift_card, list_gift_cards, update_gift_card. Events: gift_card.created, sent, used, updated.
- automatic discounts: discounts.create({ automatic: true, kind, value, min_subtotal?, ends_at? }) applies to every qualifying checkout without a code (store pages, agents and your own checkouts); code is optional and only names it on the receipt. Best one wins; one discount per checkout, so a discount_code replaces it. MCP: save_discount with automatic: true.
- discounts: create({ code: "SUMMER20", kind: "percent" | "amount", value (1–100 or cents), min_subtotal?, max_redemptions?, starts_at?, ends_at? }), list(), get(idOrCode), update(idOrCode, {...; active?}), delete. Live codes work on Stripe's checkout page automatically; checkouts.create({ discount_code }) applies one up front. Orders record `discount` and `discount_code`.
- abandoned checkout recovery: on by default. When a checkout expires unpaid, Stripe makes a recovery link and the shopper gets one email (US shoppers can opt out at checkout; elsewhere only opt-ins), plus a checkout.abandoned event with { email, recovery_url }. Turn off: store.update({ recovery_emails: false }).
- checkouts: create({ items: [{ variant_id, quantity, properties?, print_files? }], success_url, cancel_url?, customer_email?, discount_code?, shipping_countries? (default ["US"]), shipping_rates?, expires_in_minutes? (30–1440), metadata? }) → { id, url, status, expires_at }; get(id)
  - error.type "out_of_stock" includes `available` and `variant_id`
  - properties: custom data per line (≤20 keys × 500 chars), e.g. { name: "Riley", parks: "Zion, Arches" }. Shown on Stripe's page, saved on the order item. Customized lines are never merged.
  - print_files: [{ placement: "front", url: "https://..." }] per-order artwork for print-on-demand (https only)
- sales tax (Stripe Tax on the merchant's account; off by default): store.tax() → { enabled, collecting, stripe: { status, missing_fields, registrations }, next_step, fix_url, last_error, categories }. store.update({ tax_enabled: true, default_tax_code: "txcd_30011000" }); per product tax_code. reports.tax({ days }) → sales and tax by state with registered/watch. A checkout never fails because of tax: if Stripe refuses, the sale proceeds without tax and last_error is set. The merchant registers and files; Stripe charges 0.5% of volume on Checkout sales in registered places. Prices that already include tax: store.update({ prices_include_tax: true }). Per-order export: reports.taxOrders({ from, to }) or GET /v1/reports/tax/orders?format=csv. store.tax().links has the Stripe pages for registrations, thresholds, filing and transactions. MCP: sales_tax_status, configure_sales_tax, sales_by_state, tax_orders.
- tax-exempt customers (wholesale, nonprofit): customers.update(email, { tax_exempt: true, tax_exempt_note: "cert #123" }) (MCP set_customer_tax_exempt; works before their first order). Checkouts you create with that customer_email then charge no sales tax, and the order has tax_exempt: true (also a column in the tax orders export). It only applies to checkouts created with the store's API key, never to public store pages or shopping agents, so a shopper can't claim someone else's exemption by typing their email. The merchant keeps the exemption certificate.
- shipping at checkout: store.configureCheckoutShipping({ countries: ["US"], rates: [{ name: "Standard", amount: 500, min_days: 3, max_days: 7 }], free_over: 7500 }) (MCP configure_checkout_shipping). Every checkout uses it unless it passes shipping_rates; without it checkouts charge $0 shipping.

## Cart for any React site

- Checkout route (server; the key stays secret): `import { createCheckoutHandler } from "commerceforai"; export const POST = createCheckoutHandler();` at app/api/checkout/route.ts. Browser sends only { items: [{ variant_id, quantity, properties? }], discount_code? }; success page /checkout/success.
- Hooks (draw nothing): `import { CartProvider, useCart, useVariantPicker, useClearCartOnSuccess, formatMoney } from "commerceforai/react"`. useCart(products) → items, lines (joined to catalog: product, variant, line_total, available, over_stock), missing, count, subtotal, ready, add(variantId, qty, properties?), setQuantity(index, qty), remove(index), fix(), checkout({ discount_code? }), pending, error. useVariantPicker(product) → options [{ name, values: [{ value, available, selected }] }], select(name, value), variant, inStock, available.
- Copy-in Tailwind components: `npx shadcn@latest add https://commerceforai.com/r/cart.json` (CartButton/CartDrawer, AddToCart, ClearCartOnSuccess, checkout route). Framework-free logic: `commerceforai/cart`.
